## How to Generate Security Credentials

Security credentials are crucial for API authentication. Here's the detailed process:

### Overview

M-Pesa Core authenticates a transaction by decrypting the security credentials. Security credentials are generated by encrypting the base64 encoded initiator password with M-Pesa's public key, a X509 certificate.

### Algorithm Steps

The algorithm for generating security credentials is as follows:

1. **Prepare Password:** Write the unencrypted password into a byte array.

2. **Encrypt:** Encrypt the array with the M-Pesa public key certificate. Use the <Highlight>RSA algorithm</Highlight>, and use <Highlight>PKCS #1.5 padding</Highlight> (not OAEP), and add the result to the encrypted stream.

3. **Encode:** Convert the resulting encrypted byte array into a string using <Highlight>base64 encoding</Highlight>. The resulting base64 encoded string is the security credential.

### Implementation Example

<CodeExample title="Security Credential Generation">
```python
import base64
from cryptography.hazmat.primitives import hashes, serialization
from cryptography.hazmat.primitives.asymmetric import rsa, padding

def generate_security_credential(password, certificate_path): # Read certificate
with open(certificate_path, 'rb') as cert_file:
cert_data = cert_file.read()

    # Load public key
    public_key = serialization.load_pem_public_key(cert_data)

    # Encrypt password
    encrypted = public_key.encrypt(
        password.encode('utf-8'),
        padding.PKCS1v15()
    )

    # Base64 encode
    security_credential = base64.b64encode(encrypted).decode('utf-8')
    return security_credential

```
</CodeExample>

## Callback and IP Whitelisting

For production security, proper callback handling and IP whitelisting are essential.

### Callback Configuration

For notification of payments, our API gateway communicates through callback to either:
- Registered URL for <Highlight>C2B</Highlight>
- Callback URL embedded as parameter for other APIs on the request body

### IP Whitelisting

The IPs you should expect to receive callback from are as below and partners are advised to whitelist and accept callback from the IPs below:

- `196.201.214.200`
- `196.201.214.206`
- `196.201.213.114`
- `196.201.214.207`
- `196.201.214.208`
- `196.201.213.44`
- `196.201.212.127`
- `196.201.212.138`
- `196.201.212.129`
- `196.201.212.136`
- `196.201.212.74`
- `196.201.212.69`

<Note type="info"><NoteInfo>Whitelisting these IPs ensures that you only receive and process API notifications that are from the Safaricom API Gateway</NoteInfo></Note>

## Production Deployment Checklist

Before going live, ensure you have:

- Valid M-PESA business account with admin access
- Downloaded and implemented production certificates
- Generated security credentials using production certificate
- Configured proper callback URLs with HTTPS
- Implemented IP whitelisting for callback security
- Tested all API endpoints in sandbox environment
- Set up monitoring and logging for production traffic
- Prepared error handling and fallback mechanisms

<Note type="tip"><NoteInfo>Keep your sandbox integration running alongside production for testing new features and troubleshooting issues without affecting live transactions.</NoteInfo></Note>
