# Account Balance

Enquire the balance on an M-Pesa BuyGoods (Till Number)

<Link method="POST" href="https://sandbox.safaricom.co.ke/mpesa/accountbalance/v1/query" />

The Account Balance API is used to request the account balance of a short code. This can be used for both B2C, buy goods and pay bill accounts.

Below are the detailed accounts for the B2C, buy goods, and pay bill short codes:

| B2C Accounts  | Pay bill Accounts | Buy Goods Accounts      | Description                                                                                                                                  |
| ------------- | ----------------- | ----------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| Utility       | Utility           | Merchant                | • This is the account that receives payments in both paybill and Buy goods.<br/>• A utility account in B2C is for the disbursement of funds. |
| Working (MMF) | Working           | Working                 | • It's a transition account that holds money awaiting settlement to the bank or your individual M-PESA account.                              |
| Charges paid  | Charges paid      | Charges paid            | • This account deducts charges incurred depending on the business tariff you are in.                                                         |
|               |                   | Organization Settlement | • After charges are deducted, money passes here to the working account.                                                                      |

**PS:** 3rd party can only check the balance of their own shortcode. In case the initiator is associated with the Merchant HO, it can request a balance query of the merchant store within the hierarchy.

## Account Balance API transaction process flow:

1. The Organization sets all the required parameters in the request and sends it to https://sandbox.safaricom.co.ke/mpesa/accountbalance/v1/query.

2. API Management platform (Daraja) receives the request validates, authorizes, and authenticates the partner to access the API, sends it to M-PESA, and a (synchronous) acknowledgment back to the Organization.

3. M-PESA receives the request and validates it internally first, then sends you an acknowledgement response.

4. M-PESA processes the request, then sends back the response via the callback URL specified in the initial request.

5. As of now, there are no repeat callbacks for failed callbacks, thus if M-PESA is unable to send the callback to you, you will need to check the status of that transaction

Now let's dive into the request:

You will first generate an access token to allow you to make the API call. See how to generate an access token here <Highlight>Authorization API link</Highlight>.
